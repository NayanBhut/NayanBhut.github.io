The problem

Shipping a TestFlight build is a sequence of small, repetitive browser tasks: upload from Xcode, wait for processing, open App Store Connect, click through Apps → TestFlight → build, write "What to Test" for every locale, assign groups and testers, then refresh the page to see whether the build is valid.

The locale step is where it gets expensive. A single build can carry release notes across 50 locales, and one missed region means an empty note for real testers. There was no native way to do this without living in the web portal.

What I built

Shipyard Connect for ASC is a free macOS 15+ app on the Mac App Store. It is the shipping version of the tool I use to prepare releases for the retail apps in my day job.

  • A native macOS app that browses apps, pre-release versions and TestFlight builds.
  • Release-note editing that writes whatsNew across every locale, with a completeness check before Save All.
  • A menu-bar monitor that polls build state every 120 seconds and posts a local notification when a build reaches a terminal state.
  • Beta operations: invite testers, assign builds to external groups, toggle auto-notify and submit external review.
  • Store-listing edits with Apple's length limits validated up front, plus review replies and app-info localisations.
  • Team resources: devices, certificates, bundle IDs and provisioning profiles — including CSR file upload.

Technical decisions

Model the API properly, not with stringly-typed dictionaries

App Store Connect speaks JSON:API, with resources, relationships and included documents. The app models that shape instead of passing loose JSON around. It is more code up front, but it makes pagination, relationship traversal and encode-only request bodies predictable — and it is the difference between a demo and a tool you trust with a production release.

Secrets stay in the Keychain, preferences stay out of it

Each team has its own API key (issuer ID, key ID and .p8). Those live in the Keychain. The last-selected team is stored as a name in UserDefaults and restored on launch — a small distinction that removed repeated Keychain prompts without ever copying a secret into preferences. The full story is in the Keychain write-up.

Swift 6 concurrency rules, enforced by the compiler

The app builds with complete strict-concurrency checking, so isolation is enforced rather than documented. The icon cache is an actor instead of an NSLock held across await; UI-bound state is @MainActor; JWT handling uses Sendable date providers. The audit that got it there touched 21 files and is written up as a separate case study.

Review the diff before a human does

The repository runs an LLM review on every pull request. When it silently truncated large diffs, the fix was to chunk on file boundaries and pass earlier findings forward, so every line is reviewed exactly once. That change is documented in Review every line of a 237k-character PR.

Ship it, then keep the source open

The app went through App Review and reached the Mac App Store as version 1.0 on 4 November 2026. The repository stays public: the build workflow, the review automation and the release checklist are all visible, and the merged pull requests below are the real review trail behind the shipped binary.

Results

  • Live on the Mac App Store — version 1.0, released 4 November 2026, free, macOS 15 or later.
  • 50 locales updated in a single Save All pass, with a completeness check.
  • Build state watched every 120 seconds, with local notifications instead of manual refreshes.
  • 37 merged pull requests in the public repository, including a strict-concurrency audit and a Keychain persistence fix.
  • Unit tests cover CSR loading and provisioning validation; the project builds with build-for-testing cleanly.
