The issue

The Android build workflow on main was invalid. GitHub Actions refused to start it: 

Invalid workflow file: .github/workflows/CreateBuild.yml#L1
(Line: 53, Col: 30): Unrecognized named-value: 'runner'

The result was a startup_failure — not a failed build, but a workflow that never ran a single step. Branches pushed by Dependabot also fell back to a file-path workflow name, which made the failure harder to spot in the Actions list.

Root cause

runner.temp was used in a job-level env block. The runner context is only available inside steps, not while the job is being configured. The workflow was syntactically plausible YAML and passed a casual read; GitHub rejected it before execution.

The path was only used for a throwaway CI upload keystore, so the environment did not need to be a runner path at all.

The fix

  • Replaced runner.temp with github.workspace, which is valid at job level: ANDROID_KEYSTORE_PATH: {% raw %}${{ github.workspace }}{% endraw %}/ci-upload.keystore.
  • The previous PR in the series had already moved the workflow to current action majors — checkout v7, setup-node v7, setup-java v6, setup-gradle v6, setup-android v4, upload-artifact v7 and cache v6 — and added job timeouts, a CocoaPods cache and a note about the CocoaPods → SPM deprecation.

Tests

  • actionlint .github/workflows/CreateBuild.yml passes.
  • The PR's own CI run validates the workflow end to end — the real proof, because the failure mode was at workflow startup.

Trade-offs

  • github.workspace is per-job. That is fine for a temporary keystore that is created and discarded inside the job, but it would be wrong for an artefact expected to survive between jobs.
  • No behavioural change to release signing. The same upload key is decoded into the same kind of temporary file; only the directory expression changed.
  • Action major upgrades are separate. Keeping the version bumps in the previous PR made this one a two-line fix that is easy to review and easy to revert.

Result: the workflow starts again, Dependabot branches get a real CI run, and the fix is verified by the workflow it repairs.
